# 試算表欄位說明（給 Hermes / Codex / 你自己手動填）

這份同時是兩個用途：

1. **你自己**想直接在 Google 試算表裡改資料時的欄位對照
2. **交給 AI 助理**（Hermes、Codex 等）時可以整份貼給它的說明

---

## 給 Hermes 的一段話（可直接複製貼上）

> 我有一個旅遊規劃工具，資料存在 Google 試算表，可以透過一個網址新增資料。
>
> 網址：`<把你的 Apps Script /exec 網址貼在這裡>`
>
> 用法：對這個網址送出一個 POST 請求，Content-Type 設成 `text/plain`，內容是 JSON：
>
> ```json
> {
>   "action": "append",
>   "sheet": "行程",
>   "device": "Hermes",
>   "rows": [
>     ["關西5天", "1", "1", "09:00", "景點", "清水寺", "京都市東山區", "記得帶現金", "", "", "400", "JPY", ""]
>   ]
> }
> ```
>
> `sheet` 可以是「旅程」「行程」「支出」「清單」其中之一，`rows` 是要新增的資料列。
> 各分頁的欄位順序見下面的對照表。
> 成功會回 `{"ok":true,"added":1,...}`，失敗會回 `{"ok":false,"error":"..."}`。
>
> 注意：`append` 只會「新增」資料列，不會修改或刪除既有的，所以不會弄壞我原本的資料。

> **提醒：** Hermes 跑在 Docker 容器裡，只看得到被掛載進去的資料夾。
> 如果要它讀某個檔案（例如 OneDrive 上的 .md），那個資料夾必須有掛載到容器裡，
> 否則它會說找不到檔案。不想改掛載設定的話，直接把檔案內容貼在對話裡給它也可以。

## 四張分頁的欄位

### `旅程` — 一列 = 一趟旅行

| 欄 | 名稱 | 說明 | 範例 |
|----|------|------|------|
| A | 名稱 | **這是識別用的主鍵**，其他分頁都靠這個對應 | `關西5天` |
| B | 出發 | `YYYY-MM-DD` | `2026-03-01` |
| C | 回程 | `YYYY-MM-DD` | `2026-03-05` |
| D | 基準幣別 | 結算結果用哪種幣別顯示 | `TWD` |
| E | 成員 | 用逗號分隔 | `Allie,小明,小華` |
| F | 匯率 | `代碼=數字`，逗號分隔 | `JPY=0.21,USD=32` |

> 匯率的意思是「1 單位外幣 = 多少基準幣別」。1 日幣約 0.21 台幣，就填 `JPY=0.21`。

### `行程` — 一列 = 一個行程點

| 欄 | 名稱 | 說明 | 範例 |
|----|------|------|------|
| A | 旅程 | 對應「旅程」分頁的名稱 | `關西5天` |
| B | 第幾天 | 從 1 開始 | `2` |
| C | 順序 | 同一天裡的先後。留空就照列的順序 | `1` |
| D | 時間 | `HH:MM`，可留空 | `09:00` |
| E | 類型 | 景點 / 吃飯 / 住宿 / 交通 / 航班 / 其他 | `景點` |
| F | 做什麼 | **必填** | `清水寺` |
| G | 地點 | | `京都市東山區` |
| H | 備註 | | `記得帶現金` |
| I | 連結 | Google Maps、訂房頁面等 | `https://maps.app.goo.gl/...` |
| J | 圖片 | 圖片網址，或專案裡的短路徑 | `images/kiyomizu.jpg` |
| K | 金額 | 只填數字 | `400` |
| L | 幣別 | | `JPY` |
| M | 參加者 | 逗號分隔。**留空白 = 全員一起** | `Allie,小明` |

#### 分頭行動怎麼填

有些日子大家會分開走 —— 早上一起、下午分組、晚上會合。
這種情況**不用建兩份行程**，只要在「參加者」欄填那幾個人的名字就好：

| 時間 | 做什麼 | 參加者 |
|------|--------|--------|
| 09:00 | 清水寺 | *(留空 = 全員)* |
| 13:00 | 環球影城 | `Allie,小明` |
| 13:00 | 心齋橋購物 | `小華` |
| 19:00 | 道頓堀晚餐 | *(留空 = 全員)* |

工具裡會把分頭的行程點標上人名、加上顏色區隔，也可以用「只看某人」篩選。
另外，從這種行程點按「加到分帳」時，**分攤對象會自動帶入參加者**，
不會把下午的門票算到沒去的人頭上。

### `支出` — 一列 = 一筆花費

| 欄 | 名稱 | 說明 | 範例 |
|----|------|------|------|
| A | 旅程 | | `關西5天` |
| B | 日期 | `YYYY-MM-DD` | `2026-03-02` |
| C | 項目 | | `午餐` |
| D | 備註 | | `小明加點了生魚片` |
| E | 金額 | **整筆的總金額** | `1000` |
| F | 幣別 | | `JPY` |
| G | 誰付的 | 成員名字 | `Allie` |
| H | 分給誰 | 逗號分隔。**留空白 = 全部的人** | `Allie,小明` |
| I | 指定項目 | 見下方 | `生魚片=100=小明` |

#### 「指定項目」怎麼填

用在「這筆錢裡有一部分只有某幾個人要負擔」的情況。

格式：`說明=金額=誰,誰`，多筆用 `|` 分隔。

**範例：午餐 1000 元，其中生魚片 100 只有小明吃**

```
金額欄：1000
分給誰：（留空，代表全部的人）
指定項目：生魚片=100=小明
```

計算方式：先把 100 算給小明，**剩下的 900** 才由「分給誰」的人均分。
三個人的話 → Allie 300、小明 400、小華 300。

**那 100 由兩個人平分：**

```
指定項目：生魚片=100=小明,小華
```

→ 小明小華各負擔 50，剩下 900 三人均分 → Allie 300、小明 350、小華 350。

**多筆指定項目：**

```
指定項目：生魚片=100=小明 | 甜點=60=Allie,小華
```

**吃生魚片的人不分剩下的錢：**

```
分給誰：Allie,小華     ← 把小明拿掉
指定項目：生魚片=100=小明
```

→ 小明只負擔 100，剩下 900 由 Allie 和小華均分（各 450）。

**規則：**
- 指定項目加起來**不能超過**總金額
- 扣掉指定項目後如果還有剩，「分給誰」就不能是空的
- 留空代表整筆都由「分給誰」的人均分（最常見的狀況）

### `清單` — 一列 = 一個打包項目

| 欄 | 名稱 | 說明 | 範例 |
|----|------|------|------|
| A | 旅程 | | `關西5天` |
| B | 分類 | | `重要證件` |
| C | 圖示 | 一個 emoji，可留空 | `🪪` |
| D | 項目 | | `護照` |
| E | 完成 | `TRUE` / `FALSE`（也接受 `是`、`V`、`1`） | `FALSE` |

## 容錯行為（填錯了會怎樣）

工具在讀取試算表時會盡量不讓資料消失：

| 狀況 | 處理方式 |
|------|---------|
| 行程列的「旅程」名稱在旅程分頁裡找不到 | **自動建立一趟新旅程**。所以 Hermes 只加行程列也能用 |
| 支出或指定項目出現名單上沒有的成員 | **自動加入該成員**並提出警告，不會把那筆錢丟掉 |
| 「第幾天」超過回程日能涵蓋的天數 | **自動把回程日往後延**，不會刪掉行程 |
| 類型欄寫了看不懂的字 | 歸到「其他」，該列其他欄位照常保留 |
| 參加者欄出現名單上沒有的人 | **自動加入該成員**並提出警告 |
| 參加者欄留空或整欄不存在 | 視為全員一起（舊資料不會壞） |
| 指定項目格式寫錯 | 略過那一條並提出警告，整筆支出的金額仍保留 |
| 匯率格式寫錯 | 略過並提出警告 |

警告訊息會在工具讀取資料時顯示出來。

## `_設定` 分頁

這張分頁是工具自己用的（記錄最後更新時間和裝置），**請不要手動修改**。

它的用途是偵測「兩台裝置都改了同一份資料」的狀況，好在覆蓋之前先問你。
